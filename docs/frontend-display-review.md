# 思考过程、代码块与命令显示专项检查

- 日期：2026-10-06。
- 结论：基础样式可用，但代码围栏、工具事件展示和复制反馈存在可复现问题；不应将上一轮接口通过等同于这些显示细节全部合格。
- 方法：在 127.0.0.1:18766 的隔离测试服务上加载未经修改的 webui.html，使用明确标注的合成思考 / 工具事件 / 代码样例；另直接执行原 Markdown 渲染函数和复制处理函数。
- 未调用付费模型，未执行示例命令，未修改 webui.html / index.js。

## 1. [P2] C++ / C# 围栏会破坏本块及后续代码块

定位：webui.html:357–359。

代码块正则只接受 `\w*` 语言标识和 LF 换行。独立的 c++、c#、CRLF 围栏均未生成 pre。更严重的是，C++ 的结束围栏会与后续 PowerShell 的开始围栏被错误配对，导致“PowerShell 命令示例”标题成为可复制代码，而真正命令变成普通文本。浏览器中已复现，不只是缺少语法高亮。

建议：按行、围栏长度和开始 / 结束状态解析 Markdown 代码块，至少支持 c++、c#、带附加信息的语言行及 CRLF；避免从不支持的开始围栏跳到任意结束围栏配对。

证据：.cache/display-review-render-cases.json；.cache/ui-review/display-review-code-bug.png。

## 2. [P2] 流式输出未闭合代码围栏时，不按代码显示

定位：webui.html:357–361、659–661、670–671。

直接执行原渲染函数，输入未闭合的 JavaScript 围栏时输出普通文本和 br，不生成 pre。实际流式正文每个片段都会走同一渲染逻辑，因此要等结束围栏到达才变成代码块。复制按钮只在整个回复结束后添加：即使前面的代码块已经输出完整，只要后面还在生成，也没有复制入口。

建议：允许未闭合围栏作为“生成中代码块”呈现；逐块维护 DOM 和复制控件，避免追加内容导致横向滚动位置重置。未完内容应明确标记，不把临时文本误当完整代码。

## 3. [P2] 剪贴板写入失败也立即显示成功

定位：webui.html:372–375。

复制处理没有等待 navigator.clipboard.writeText 的 Promise，直接把按钮变成勾号。以拒绝 Promise 的剪贴板替身执行原函数，按钮依然显示 ✓；用户可能继续粘贴旧内容。

建议：成功后才显示“已复制”；API 缺失或拒绝时显示“复制失败，请手动选择”，捕获异常，并使用可访问状态提示。

## 4. [P2] 命令卡片缺少实际命令及执行结果，不能承担执行记录用途

定位：webui.html:648–653；index.js:3549–3557、4578。

后端已经发送 tool_call.name 与 tool_call.args，但前端只显示工具名。测试发送了 bash_tool 及明确的 command，页面仍只出现“🔧 bash_tool”。卡片没有 shell、工作目录、命令、执行状态或退出码。

后端当前的回调发生在执行工具之前，流中没有对应的结构化完成结果。因此不能只在前端把这类事件标成“执行成功”；必须增加可关联的生命周期事件，再展示开始、成功 / 失败 / 拒绝 / 中止、标准输出 / 错误和退出码。

建议：先展示经脱敏的具体命令和“已请求”状态；再补调用 ID、执行生命周期与结果。输出折叠、限制体积；示例命令代码块与真实执行卡片在视觉和文案上明确区分。不能直接无筛选展示全部工具参数，其中可能包含密钥。

## 5. [P2] 多阶段思考与工具顺序被合并、重排

定位：webui.html:636–645、652、659。

所有 reasoning 都追加到同一个 thinkAcc，并放在回复最前。第一段正文到达就自动收起该容器，工具执行后到达的后续思考仍追加到已收起的第一块。合成“阶段一 → 正文 → 工具 → 阶段二 → 正文”事件后，浏览器得到“两个阶段合并的思考 → 工具卡片 → 所有正文”。这不是原始事件顺序，也无法清晰表示正在思考还是执行工具。

建议：按阶段维护事件时间线；默认以思考状态 / 摘要呈现，详细信息允许展开；不要反复覆盖用户的展开选择。滚动仅在用户接近底部时自动跟随。纯思考后直接结束或报错时，也应有明确终态。

## 6. [P2] 会话恢复后思考及工具卡片消失

定位：webui.html:670–673，及会话保存 / 恢复路径。

历史数组只加入 assistant 正文。浏览器刷新前有 1 个思考容器、1 个工具卡片；刷新并恢复会话后两者均为 0，正文仍存在。用户无法从聊天记录回看刚才的命令活动。

建议：把用于界面回放的结构化活动记录与发送给模型的聊天上下文分开保存，优先保存命令摘要与结果；思考详情是否保存应作为明确的数据保留策略，而不是隐式消失。不要为了显示回放把工具结果重复注入下一轮模型上下文。

## 已确认合理的部分

- 思考过程与正文使用独立容器，详情可折叠，展开内容有 300px 高度限制。
- 思考内容以 textContent 写入；工具名称经过转义；普通已闭合 JavaScript 代码可以保留缩进和中英文字符。
- 代码采用等宽字体与独立背景，已完成的有效代码块有复制入口。
- 本次桌面测试页面没有整体横向溢出。

## 次要体验改进

- 语言标识当前被丢弃，无法在代码块头部确认是 JavaScript、PowerShell 还是 Bash；建议补语言标签。
- 语法高亮、行号属于可选增强，优先级低于正确解析、真实状态和复制可靠性。
- 流中每个正文片段都重建 HTML，可能干扰长代码的阅读及选中操作；建议增量渲染。
- 停止 / 错误分支会移除整个 assistant bubble（webui.html:677），已展示的部分代码和工具卡片也会消失；建议保留已接收内容并标记中断。
