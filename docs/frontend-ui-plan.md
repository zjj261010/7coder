# 7coder 前端界面优化方案

- 日期：2026-10-05
- 范围：`webui.html` 的布局、样式、前端交互，以及界面回归测试。
- 原则：保留现有聊天、流式回复、审批、会话、任务、模型配置接口；不引入框架、在线字体或运行时依赖；兼顾离线运行；保留工作区已有修改。

## 一、现状与目标

现有界面是深色单页聊天工作台。主要不足：侧栏配置与导航混在一起，视觉层级弱；初始页面只有一条问候消息；输入区缺少明确状态；设置面板固定宽度，不适合手机；按钮语义和键盘焦点支持不完整。

目标：形成安静、清晰、中文友好的开发工作台。用户能快速理解当前位置、开始任务、找到历史和配置，并在桌面与手机上完成相同的核心操作。

## 二、设计方案

### 1. 视觉系统
- 默认使用暖白画布、浅灰侧栏、石墨色文字、橙色主操作；提供可记忆的深色主题。
- 使用系统中英文字体，不请求外部资源；统一行高、圆角、间距、边框与焦点样式。
- 使用内嵌 SVG 线性图标替代主要导航中的杂乱符号；状态同时用文字表达，不仅依赖颜色。
- 轻量过渡动画，并尊重减少动态效果的系统偏好。

### 2. 信息结构
- 左侧：品牌、新建对话、历史搜索与会话列表、任务列表、模型与权限、工作区/配置入口。
- 顶部：当前工作区、权限状态、真实连接状态、主题切换。
- 中间：无会话时显示欢迎页、三张任务建议卡片；有会话时聚焦聊天消息。
- 底部：统一输入容器，展示所选模型、发送/停止按钮、快捷键与操作范围说明。

### 3. 核心交互
- 建议卡片只填入可编辑的任务提示，不自动发送，不模拟已有会话或执行状态。
- 历史会话支持本地过滤、当前项高亮、独立删除按钮，以及空状态/加载失败反馈。
- 空输入禁用发送；中文输入法组合输入期间，回车不触发发送。
- 新建对话恢复欢迎页；避免忙碌时切换会话导致界面与请求上下文错位。
- 模型设置使用分组抽屉，增加遮罩、Escape 关闭、焦点管理与窄屏布局；保留原有保存接口。
- 权限名称如实说明：auto 为自动判断，不表达成无条件放行；bypass 保留风险提示。

### 4. 响应式与可访问性
- 桌面保留侧栏；768px 以下改为可关闭的侧栏抽屉，提供遮罩。
- 设置抽屉宽度不超过视口，模型配置行在窄屏纵向排列。
- 320px 起不出现页面横向溢出；长路径、省略标题、长代码块均有溢出处理。
- 点击入口使用原生 button；输入框有明确 label；图标按钮有可访问名称；键盘焦点可见。
- 设置和侧栏覆盖时限制焦点范围，关闭后返回触发入口。

## 三、实施顺序

1. 保存本方案，之后再修改界面。
2. 重建视觉变量、页面布局、欢迎页与响应式样式。
3. 接入主题、搜索、抽屉、输入状态与空状态交互，保留原接口。
4. 新增无外部依赖的前端回归测试，运行相关已有测试。
5. 启动仅本地可访问的预览，以测试数据检查桌面、手机、主题与设置布局；不使用真实模型密钥、不发送真实付费请求。
6. 将执行结果和已知限制追加到本文件。

## 四、验收标准

- 首屏有明确的产品标识、任务入口、输入区与状态，不展示伪造的业务数据。
- 聊天发送/停止、流式输出、会话恢复、审批、模型配置功能保留。
- 欢迎卡片、历史搜索、主题记忆、新建对话、设置抽屉和键盘行为可验证。
- 桌面与手机无明显遮挡和横向溢出，浅色/深色下正文与交互均清晰。
- 既有修改保留；后端无本次无关改动；新增运行时依赖为零。
